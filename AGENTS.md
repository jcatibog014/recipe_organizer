## Overview

**Sangkap** ("ingredient"), a recipe organizer in Python (Flask). The repo is `recipe_organizer` and the Python package is `sangkap`. It stores recipes (ingredients with amounts, steps, tags, a photo) and finds them **by ingredient**. It also has Discover (ready recipes from TheMealDB), share links, a meal plan and a shopping list. The roadmap is `docs/PLAN.md`.

It is a learning project for **data modeling, search and many-to-many relationships**, so the data model and the search SQL should stay easy to read: short comments that explain *why*, and no extra libraries unless the owner asks for them. Write the README in simple (A1-level) English.

Python 3.13 is at `%LOCALAPPDATA%\Programs\Python\Python313\python.exe`. Use the virtual environment:

- Install: `.venv\Scripts\python -m pip install -r requirements.txt` (create `.venv` with `python -m venv .venv` first if it's missing).
- First time: `.venv\Scripts\flask --app sangkap upgrade-db` (makes the tables + the starter ingredients), then `.venv\Scripts\flask --app sangkap create-user <name>`.
- Run: `.venv\Scripts\flask --app sangkap run --debug --port 5003`, then open http://127.0.0.1:5003. (Port 5003: Swap Meter uses 5000, Ambon Alert 5001, Ang Gastos! 5002.)
- Test: `.venv\Scripts\python -m pytest`. Every test gets a fresh SQLite file and **never uses the internet** (TheMealDB answers come from `tests/fixtures/mealdb/`). Set `TEST_DATABASE_URL` to an **empty** Neon branch to run the same tests on PostgreSQL (each test drops and remakes the tables). SQLAlchemy warnings fail the tests (`pytest.ini`).
- Other commands: `set-password <name>`, `reset-demo`.
- Screenshots: `docs/take_screenshots.py` (Playwright + Edge, logged in as the demo). Icons: `docs/make_icons.py`. Background tile: `docs/make_background.py`.

## Architecture

- **Database:** SQLAlchemy 2.0 ORM (typed `Mapped[...]` models), plain (not Flask-SQLAlchemy). `sangkap/db.py` makes one engine per app (`app.extensions["sangkap_engine"]`) and one session per request: `db.session()`. Nothing is saved without `.commit()`; the session closes on teardown. `expire_on_commit=False`. SQLite locally (`instance/sangkap.sqlite`, git-ignored; foreign keys turned on per connection), PostgreSQL (Neon, psycopg 3) when `DATABASE_URL` is set; `database_url()` adds `+psycopg`. Keep code portable: no dialect-only SQL.
- **Migrations: Alembic**, in `sangkap/migrations/` (`env.py` takes the app's connection, or builds the URL itself from the command line; `render_as_batch` on SQLite). `flask --app sangkap upgrade-db` = `alembic upgrade head` + `ingredients.add_catalog()`; Render runs it before gunicorn.
  - **To change the schema:** edit `models.py`, then `.venv\Scripts\alembic revision --autogenerate -m "what changed"`, **read the new file and fix it**, and commit it. Never edit a migration that has run on the live site. `tests/test_migrations.py` fails if the models and the migrations disagree.
  - Constraint names come from `NAMING_CONVENTION` in `db.py`.
- **`sangkap/models.py` is the data model** (diagram at the top): `User`, `Recipe`, `Ingredient` (the shared catalog), `IngredientAlias`, `RecipeIngredient`, `Step`, `Tag`, `recipe_tags`, `Photo`, `PlanEntry`.
  - **Two many-to-many patterns:** `Recipe.tags` uses the plain `recipe_tags` Table (`secondary=`); `Recipe.ingredients` is a list of **association objects** (`RecipeIngredient`: amount, amount_max, unit, note, is_optional, section, position).
  - The same ingredient may be in one recipe twice (no UNIQUE on recipe+ingredient); search counts `DISTINCT`.
  - `Recipe.ingredients` / `.steps` use `ordering_list("position")` and `cascade="all, delete-orphan"`. Deleting a recipe deletes its lines, steps, tag links, photo and plan entries. `recipe_ingredients.ingredient_id` is `ON DELETE RESTRICT`: merge an ingredient instead of deleting it.
  - `Photo.data` is `deferred`, so listing recipes never loads image bytes. Times are naive UTC (`dates.utcnow()`); `dates.today()` is Philippine time.
  - When building a recipe, **find/add every catalog ingredient first, then build the lines inside `with s.no_autoflush:`** (see `views/recipes.save()`), or SQLAlchemy flushes half-built rows.
- **Privacy:** recipes, tags and plan entries have `user_id`, and every query filters on `g.user.id`. Someone else's row gives 404 (`views.owned_recipe()`, `tags.owned_tag()`). The ingredient catalog is shared: `ingredients.suggestions()` and the ingredient pages only show starter ingredients + ones *your* recipes use; `merge()` only moves *your* lines. Tests check the demo can't see the owner's things.
- `sangkap/ingredients.py`: `CATALOG` (≈115 starter ingredients: name, kind, Filipino/English aliases), `normalize()`, `resolve()` (name → alias → simple plural), `get_or_create()`, `add_catalog()` (safe to repeat), `usage()` (`GROUP BY` counts), `merge()` (rename/merge; keeps the old name as an alias when nobody uses it any more; not for the demo), `delete_unused()`, `emoji_for()`.
- `sangkap/quantities.py` (pure): `parse_amount()` ("1 1/2", "½", "2-3" → numbers, or `ValueError` with a message), `split_quantity()` (amount + unit off the front of a text), `format_quantity()` (1.5 → "1 ½ cups"), `UNITS`/`UNIT_ALIASES`/`UNIT_CHOICES`, `CONVERSIONS` (mass/volume families for the shopping list).
- `sangkap/paste.py` (pure): pasted lines → rows (bullets, "(optional)", "to taste", notes after a comma or in brackets, "Heading:" lines). The demo recipes in `seed.py` are written in this format.
- `sangkap/validation.py` (no Flask): `validate_recipe(form)` → `(data, errors)`. The form's ingredient rows are **parallel lists** (`row_kind`, `row_section`, `row_amount`, `row_unit`, `row_name`, `row_note`, `row_optional`); every row sends every field. `data["form_rows"]`/`["form_steps"]` keep what was typed, with per-row `error`.
- `sangkap/search.py`: ALL the search SQL. `Query` (have / without / mode `all|any|pantry` / missing_max / text / tag_ids / max_minutes / favorites / staples) → `build()` (the `select()`) → `run()` (results with matched / missing / optional names). `ingredient_counts()` is the sub-query with `COUNT(DISTINCT CASE ...)`. `STAPLES` (water, salt, oil, pepper) never count as missing when that box is on. Results load with `selectinload` (no N+1; a test counts the queries).
- `sangkap/mealdb.py` (no Flask): TheMealDB with the free key `1` (allowed for educational use). `FETCH_JSON`/`FETCH_BYTES` are swapped in tests. In-memory cache (`_cache`). The free key filters by ONE ingredient, so `by_ingredients()` intersects ids in Python; `best_name()` picks the alias TheMealDB knows (eggplant → aubergine). `to_recipe()` maps the flat `strIngredient1..20`/`strMeasure1..20` row into our shape. Pictures only from `https://www.themealdb.com/` (CSP `img-src`). Always credit "Recipe data and imagery: TheMealDB".
- `sangkap/shopping.py` (pure): `build(plan_entries)` → items per shelf (`KINDS` order), scaled to the planned servings, units of one family combined into the biggest one used; optional lines left out.
- `sangkap/photos.py`: Pillow; ≤ 1000 px WebP, EXIF (GPS) dropped, `MAX_IMAGE_PIXELS` guard. `sangkap/display.py`: `ingredient_groups()` (works on ORM rows or dicts), `accent_class()` (the candy strip on a card without a photo), `wanted_servings()`.
- `sangkap/auth.py`: login/logout, `POST /demo`, `/settings`, `/settings/export` (JSON backup), CSRF (`check_csrf`; every POST form needs `{{ csrf() }}` from `_macros.html`; tests use `post()` from `conftest.py`), lock after 5 wrong passwords, the CLI. The demo (`is_demo`) is reset by `seed.reset_demo()` when over an hour old: 20 Filipino recipes + a week's plan. Demo limits: 60 recipes, 10 Discover saves, 60 plan entries, no password change, no catalog aliases.
- `sangkap/views/`: `recipes` (`/`, `/recipes/...`: list with sort/tag/favorites, show with `?servings=`, add/edit form with server-side "more rows" and "paste" actions (`action` field), photo, favorite, share, cook), `search` (`/search`, GET, bookmarkable), `ingredients`, `tags`, `discover` (`/discover`, follow, save once: UNIQUE(user_id, source, external_id)), `plan` (`/plan?week=`, `/plan/shopping`), `shared` (`/r/<share_code>`: public, read-only, no notes or owner, `noindex`), `main` (`/healthz`, `/styleguide` in debug only).
- **Theme: bright kawaii.** `static/style.css`: candy colours are fills only, text is always cocoa (light) or cream (dark), ≥ 4.5:1. Dark mode is defined twice (system setting + the toggle); change both blocks together. Puffy "jelly" buttons (`.button`, with a ledge shadow that presses down), pillow `.card`s, glossy `.chip`s. The background pattern is `body::before` at `--pattern-opacity` (0.4 light / 0.25 dark): `static/art/pattern-emoji.svg` until the owner's tile `static/art/pattern.webp` exists (`HAS_PATTERN_TILE`). Animations stop under `prefers-reduced-motion`. `static/app.js` only adds extras (theme toggle, row editing, cook mode + wake lock, shopping ticks in localStorage); every page works without JavaScript. No inline scripts (the CSP blocks them).
- **UI rules (the owner's priority is neatness):**
  - **No decorative emoji** in tabs, headings, buttons, labels or messages. Emoji are only for the big illustration in an empty state, plus ♥ (favorite) and ✓ ✗ ✕ as symbols.
  - **Pictures only when real:** a recipe with a photo shows it; one without gets a compact card with a candy strip (`.no-photo` + `accent_class()`), never a stand-in picture.
  - Sentence case everywhere ("Add a recipe", "Meal plan"); plain, correct English; the main button of a page is last on the right.
  - Layout helpers: `.page-head` (title + `.actions`), `.back-link` above the title, `.page-intro` under it, `.card-head` (card title + control), `.fields-row` and `.toolbar` (controls bottom-aligned, same height). Don't use inline `style=""` for layout.
  - Header: logo, tabs and actions on one row; under 1040px the tabs move to a second, sideways-scrolling row.
  - Filters with `data-autosubmit` apply on change; their `data-autosubmit-button` only shows without JavaScript.
  - Cook mode slides steps with the Web Animations API (`slideFrames()` in `app.js`), swipe included; reduced motion = fade.
